# Підготовка до захисту лабораторної 4

## Байти та символи

InputStream/OutputStream працюють з байтами, Reader/Writer - із текстом. InputStreamReader декодує байти за вибраним кодуванням. UTF-8 підтримує українські літери; одна літера не обов’язково займає один байт. BufferedReader і BufferedWriter накопичують дані, зменшуючи кількість дрібних системних операцій.

## Кінець файлу

readLine повертає null при EOF, read повертає -1. Порожній рядок є "", а не null. Змінна symbol має тип int, щоб відрізняти -1 від char. Значення -1 не записується. Посимвольний код передає UTF-16 елементи до writer, який кодує їх у UTF-8.

## Ресурси

try-with-resources викликає close і при успіху, і при винятку. Закриття writer виводить буфер. Без close/flush останні символи можуть залишитися у пам’яті. IOException є перевірюваним винятком: його треба перехопити або оголосити через throws.

## Шляхи й режими

Відносний шлях data/first.txt обчислюється від робочої теки процесу. Конфігурації запускають програму з кореня її проєкту. CREATE створює файл, WRITE відкриває запис, TRUNCATE_EXISTING очищує старий вміст, APPEND дописує. Батьківська тека повинна існувати; помилковий шлях можна ввести повторно.

## Списки слів

Роздільники: пробіли та . , : ;. ArrayList зберігає всі входження. Locale.ROOT усуває залежність від регіональних налаштувань. TreeSet прибирає повтори та впорядковує слова. retainAll залишає спільні елементи. Природний порядок String використовує Unicode, а не спеціальне українське словникове сортування.

## Один читач консолі

Два різні Reader або Scanner над System.in можуть наперед забрати дані у власні буфери. Тому один CONSOLE спочатку читає шляхи через readLine, потім текст через read. EOF у запиті припиняє програму, щоб не утворився нескінченний цикл.

## Можливі питання

**Чим readLine відрізняється від read?**

Перший читає рядок без кінцевого переходу, другий - один символьний елемент як int.

**Чим null відрізняється від порожнього рядка?**

null означає EOF, порожній рядок є прочитаним рядком без символів.

**Навіщо буферизація?**

Вона об’єднує дрібні операції вводу-виводу в більші й зменшує системні витрати.

**Коли закривається файл?**

На виході з try-with-resources, також у разі винятку.

**Чому read повертає int?**

Потрібно представити char та окремий маркер -1.

**Що робить APPEND?**

Додає дані в кінець, зберігаючи попередній вміст.

**Як завершити ввід на Mac?**

Надіслати EOF через Ctrl+D на початку нового рядка.

**Навіщо один CONSOLE?**

Щоб кілька незалежних буферів не конкурували за System.in.

**Чи зберігаються повтори?**

У списках вхідних слів так; у спільній множині ні.

**Що при неправильному шляху?**

Повідомлення про помилку та повторний запит; EOF завершує запити.
